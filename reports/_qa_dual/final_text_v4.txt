Self-Refine 在两个数据集上均未形成相称的准确率—token 交换。所有高级协议相对 Direct 的逐

题提升都有极强统计证据；由于当前结果包没有高级协议之间的配对检验、跨数据集交互检验或多

1. 实验背景与研究问题

1.1 背景

  大语言模型可以在不改变模型权重的情况下，通过显式展开推导、重复采样或自我反馈提高任

务表现。此类推理时扩展通常以更多模型调用、token 和等待时间换取更高准确率，因此只报告准

确率不足以支持实际部署。本实验以“推理时 token 经济性”为核心，在同一模型和硬件上比较六

种完整推理协议，并检验这些协议在基础算术文字题与更复杂的数学推理题上是否呈现一致的性

能—成本规律。


  本报告所称“经济性”是实验性的工程概念，由准确率、输入/输出/总 token、调用次数、生

成时延、协议级 call-summed end-to-end 时延、峰值已分配显存和每个成功答案的摊销 token 成

本衡量。实验没有测量货币费用、功耗、能耗或并发吞吐。


1.2 研究问题

  1. 相较于只输出最终答案的 Direct，CoT、Self-Consistency 和 Self-Refine 能否在 GSM8K 与

      MATH-500 上提高准确率？

  2. 从 CoT 继续增加采样数或反思轮数后，准确率收益是否能覆盖新增 token 与时延？

  3. 不同协议在两个数据集上的 Pareto 归属与成本排序是否一致？

  6. 面向不同可靠性与预算约束，应如何选择推理协议？

2.3 答案抽取、投票与计分

  输出优先抽取最后一个 FINAL_ANSWER:，其次抽取最后一个 \boxed{}。GSM8K 还允许退回全

文最后一个数值，预测与 gold 经数值规范化后用 Decimal 精确相等计分。MATH-500 不使用数值

回退；预测与 gold 交由 math-verify 解析并判断数学等价。


  Self-Consistency 在 GSM8K 上对数值规范化后多数投票；在 MATH-500 上先用 math-verify

将等价表达式聚类，再选择样本数最多的等价类。若平票，则选择最早出现的有效候选；若全部无

效，则退回第一个候选。Self-Refine 的 critique 阶段只检查候选，不直接产生新答案；revision 阶

段根据原题、候选与 critique 重新生成最终解。


  MATH-500 推理时只把 problem 字段传给模型，标准答案仅在生成完成后用于评分，solution

字段不进入 prompt；代码层面未发现直接标签泄漏。这里使用的是本项目基于 math-verify 0.8.0

2.4 实验流程

   1. 从 ModelScope 下载并冻结两个数据快照，记录字段、行数、fingerprint 与文件 SHA-256。

   2. 读取对应 YAML，校验模型精度、数据集、样本数、生成上限和协议清单。

   3. 本地加载 Qwen2.5-7B-Instruct；每个协议进程开始时执行一次不计分、不计 token 和时延

         的 warm-up。

   4. 对固定题目清单逐题运行目标协议；每次调用记录输入、输出、总 token、生成时延、call-

         level end-to-end 时延、峰值已分配显存和是否触及生成上限。

   5. 使用任务专用规则抽取、规范化并评分最终答案；Self-Consistency 额外记录候选投票信息。

   6. 分析器校验各协议样本数、sample ID 集合和 token 算术，随后生成汇总指标、bootstrap 区

         间、McNemar 检验与图表。


2.5 指标定义

    准确率定义为 Accuracy = correct_count / N。平均总 token 是一次协议中所有模型调用的 input

token 与 output token 之和，再对题目求平均。相对 token 成本定义为 MeanTotalTokens(protocol)

/ MeanTotalTokens(Direct)。


    tokens_per_correct = 全测试集总 token / 正确题数 = 平均每题总 token / 准确率。该指标更

准确的中文名称是“每获得一个正确答案的摊销 token 成本”：它把失败题的消耗也计入，不是只

在答对样本上统计的平均回复长度，也没有单独的置信区间。


    CoT 与 Direct 的摊销成本比可以写成：TPC_CoT / TPC_Direct = token 倍率 / 准确率倍率。因

2.6 统计方法

   准确率采用 10,000 次 percentile bootstrap 的 95% 置信区间；每个高级协议相对 Direct 的

准确率差值采用逐题 paired bootstrap 95% 置信区间；配对二元正确性差异采用双侧 exact

McNemar 检验。Pareto 前沿基于协议级平均总 token 与准确率点估计：若另一协议 token 不更

多、准确率不更低且至少一项严格更优，则当前协议被支配。


   当前分析共报告两个数据集各五个“高级协议 vs Direct”检验，没有执行多重比较校正。所有

原始 p 值远小于 0.005，因此即使用十次检验的简单 Bonferroni 阈值，定性结论仍不改变；但表

中的置信区间仍是逐比较、未校正区间。高级协议之间以及 dataset × protocol 的差异没有正式检

验。

7. 讨论

7.1 跨数据集稳定发现

  第一，CoT 是两个数据集共同的关键性能拐点。它只使用一次模型调用，却分别带来 66.79 和

44.20 个百分点的准确率提升，远大于后续采样或反思的增量。


  第二，Self-Consistency 可以继续提高准确率点估计，但每一步都显著增加 token 与串行等待

时间。两个数据集上 SC@5 的平均 token 都约为 CoT 的 4.99 倍；沿前沿从 CoT 到 SC@3、再

到 SC@5 的准确率—token 斜率均递减。


  第三，当前 Self-Refine 在两个数据集上都不具二维 token 经济性。增加 critique/revision 主

要扩大输入上下文，没有获得稳定的正确数提升。


  第四，二维经验 Pareto 前沿在两个数据集上完全一致：Direct、CoT、SC@3、SC@5 分别对应

从最低成本到最高准确率点估计的四个区间。这一一致性是点估计层面的工程规律，不代表各前沿

点之间差异都显著。


7.2 数据集依赖性发现

  CoT 是否降低成功答案摊销成本并不稳定。GSM8K 中，准确率倍率超过 token 倍率，因此

tokens-per-correct 下降；MATH-500 本次结果中，平均推导输出更长，token 增长倍率超过准确率

倍率，因此该指标上升。旧的“CoT 是所有场景下最低 tokens-per-correct 方案”结论应修正为：

CoT 只在 GSM8K 上取得全局最低值；在 MATH-500 上，Direct 最低，但 CoT 是达到约 70% 准

确率区间的最低成本方案。

     QWEN TOKEN ECONOMY | GSM8K + MATH-500 实验报告




     Self-Consistency 的后续点估计收益也具有数据集依赖性。SC@5 相对 CoT 在 GSM8K 只增加

1.97 个百分点，在 MATH-500 增加 7.20 个百分点。由于没有高级协议之间的 paired 检验与正式

交互检验，这一差异应作为后续实验动机，而不是确定性结论。


7.3 对“最佳协议”的解释

     “最佳”取决于优化目标。若只追求最低每题 token 或最低时延，Direct 最优；若要求进入较

高准确率区间，CoT 是共同的最低调用数方案；若只看最高准确率点估计，SC@5 在两个数据集上

都最高；若看 GSM8K 的每成功答案摊销成本，CoT 最优；若看 MATH-500 的同一指标且不设准

确率门槛，Direct 最优。报告不把单一指标包装成通用结论。

9. 有效性威胁与局限性

9.1 内部有效性

   Direct、CoT、Self-Consistency 与 Self-Refine 同时改变提示形式、解码随机性、调用次数和上

下文长度，协议间差异是组合处理效果，无法分离“推理文字”
                           “采样”
                              “投票”或“额外计算”各

自的独立贡献。两个完整实验都只有一个 run seed；代码虽设置 Python、PyTorch 与 CUDA seed，

但未启用严格确定性算法，跨环境不保证逐 token 一致。


   smoke、pilot 与 main 配置均使用 test split。MATH-500 v3 的 2,048 / 2,048 token 上限是在同

一 test 集的 20 题 smoke 检查后提高的，而 smoke 样本是 500 题主实验的子集；即使调整目

标主要是解析与截断质量，这仍构成测试集适配风险。仓库没有预注册或完整配置冻结时间线。

MATH-500 还存在旧版 main 与最终 v3 配置，报告虽然只采用 v3，但应在归档中明确版本演进

原因。公共 MATH-500 是否进入模型预训练数据也未做污染检测。


9.2 统计结论边界

   bootstrap 区间反映题目抽样不确定性，不反映随机解码的 seed-to-seed 波动。配对 bootstrap

与 exact McNemar 只比较各高级协议和 Direct；没有高级协议两两检验、置信区间多重校正或

dataset × protocol 交互检验。Pareto 与 tokens-per-correct 基于点估计，也没有归属或差值的不




   28
   QWEN TOKEN ECONOMY | GSM8K + MATH-500 实验报告




确定性区间。


9.3 测量边界

   实验时延来自单样本、串行调用和单卡环境，不含模型加载、服务排队、网络和大部分协议编

排开销，不能直接外推到 batch 或并发服务。峰值显存是 PyTorch max_memory_allocated，不是整

卡实际占用。两个数据集使用不同生成上限和评测器，跨数据集 token、截断和解析率不能作严格

同口径因果归因。


9.4 外部有效性

   实证范围只覆盖一个 7B 模型、两个数学数据集、一个硬件平台和一个主随机种子。结果不能

直接推广到更大模型、中文任务、代码生成、开放式问答、不同 GPU 或量化模型。GSM8K 与 MATH-

500 都是标准答案型数学任务，不能代表长文生成或主观评测任务。

11. 结论

   在 Qwen2.5-7B-Instruct、BF16、单张 A100 80GB 和单随机种子 20260730 的固定条件下，CoT

是 GSM8K 与 MATH-500 共同的关键推理协议变化：它分别将准确率从 23.96% 提升至 90.75%、

从 26.60% 提升至 70.80%。Self-Consistency 继续把最高点估计提高至 92.72% 和 78.00%，但

SC@5 在两个数据集上都需要约 5 倍 CoT 的平均 token；Self-Refine 则未形成相称的准确率收益，

并在两个数据集的准确率—token 点估计比较中处于劣势。


   双数据集结果同时否定了一个过度概括：CoT 并不必然降低每个成功答案的摊销 token 成本。

它在 GSM8K 上使该指标下降 22.2%，却在 MATH-500 上使其上升 77.9%。因此，可靠性阈值、任

务类型与成本指标必须联合决定协议选择。当前证据支持把 CoT 视为进入高准确率区间的默认起

点，把 SC@3/SC@5 保留给准确率优先且预算充足的场景，并暂缓采用现有 Self-Refine 配置。SC@5

的最高准确率与 MATH-500 上更大的采样收益仍需高级协议间配对检验和多随机种子实验确认。
